# Client and workstation platform research

Research snapshot: 2026-09-30. This is a vetted seed set, not an exhaustive OEM compatibility matrix or a claim of current orderability. It covers exact ChipIndex CPU names already present in the generated catalog. Server research and the overall generation cutoff are tracked separately.

## What a source proves

- **OEM-documented option:** An OEM's product-family specification or owner's manual names the exact CPU in its processor options. This supports a CPU-to-system-family link. It does not prove that every configuration or region has that CPU, or that it is currently for sale.
- **Published configuration:** An OEM's individual model, machine type, or product-number page names the exact CPU. This supports an actual published configuration. It still does not prove present inventory.
- **Processor category:** AMD and Intel product pages describe their CPU's market or form-factor category. Keep this separate from the physical form factor of each OEM system. For example, AMD lists the Ryzen AI 7 PRO 350 for both laptops and desktops, while Intel labels the Core Ultra 7 258V as Mobile. The exact OEM system decides whether a displayed result is a notebook, all-in-one, tiny desktop, tower, or workstation.

Use the [generated catalog's stable `products[].id`](../../js/data/benchmark-catalog.json) to join a platform relation to a CPU. The catalog intentionally distinguishes products that share a display name; `model` text alone is not a safe key. Store OEM system details once and link many exact CPUs to the system. Preserve the OEM's precise name and any model code or machine type. Each relation needs its own `evidenceType`, source URL, source title, retrieval date, and market/region when applicable. Separate a source's document date from the date we checked it.

Do not build links by socket, chipset, generation, suffix, CPU vendor partner list, search snippet alone, or a marketing phrase such as "up to Ryzen AI 9." A generic family option must not be displayed as a purchased model's installed CPU. An absent relation means **not yet verified**, not incompatible. A newly published OEM PDF can add options or revise system details, so retain verification dates and periodically recheck live source links.

## Source and extraction workflow

1. Start from one displayed ChipIndex CPU's exact catalog identity. Record vendor, exact CPU string, and any manufacturer product ID. Use [AMD's Ryzen 7 8700G page](https://www.amd.com/en/products/processors/desktops/ryzen/8000-series/amd-ryzen-7-8700g.html), [AMD's Ryzen AI 7 PRO 350 page](https://www.amd.com/en/products/processors/laptop/ryzen-pro/ai-300-series/amd-ryzen-ai-7-pro-350.html), or [Intel's Core Ultra 7 258V page](https://www.intel.com/content/www/us/en/products/sku/240957/intel-core-ultra-7-processor-258v-12m-cache-up-to-4-80-ghz/specifications.html) for processor-side category and identity, not OEM system compatibility.
2. Find exact CPU text in official OEM system specifications. Lenovo PSREF PDFs are particularly structured: the processor table, memory, dimensions, and form factor are usually in one document. Dell owner's manuals often have an explicit supported-processor table. HP product-number pages, HP QuickSpecs, and ASUS technical-specification tables can prove a family option or an individual configuration depending on page granularity.
3. Save the exact OEM product name, variant/code, evidence level, and source URL. For a Lenovo family PSREF, look for a PSREF **Detail** page with an exact machine type when a shipped configuration is useful. For HP, record the full product number. For ASUS, record the H7606 variant. Do not elevate option evidence to configuration evidence.
4. Extract only platform-level facts in the same OEM document: system form factor, chassis dimensions, notebook display size, processor-socket count for workstations, installed memory slot/channel information where explicit. Do not copy CPU maximum memory channels into a system's installed-channel field. Attach a source to each distinct fact or keep the fact out.
5. Normalize aliases only after manual review (`Intel Core Ultra7 258V` and `Core Ultra 7 258V` are an example of typography drift). Preserve source wording alongside normalized catalog identity. Deduplicate a platform shared by several CPUs, while retaining separate CPU-to-platform evidence.
6. Run ingestion checks for valid catalog IDs, unique OEM platform IDs, no duplicate CPU/platform pair, all source URLs present, and evidence type displayed honestly. Spot-check one result per OEM in the dashboard. Revisit selected OEM sources on a schedule because regional options and product pages change.

The first public client slice should focus on a small set of recent, high-interest CPUs across AMD and Intel and show the evidence label on each OEM system card. Coverage can then expand by OEM and generation without suggesting that an unresearched system is unsupported.
