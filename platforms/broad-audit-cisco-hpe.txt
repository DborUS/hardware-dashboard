Independent Cisco/HPE broad AMD FAE audit — 9 October 2026
Build audited: catalog 1.1.0, reviewed 2026-10-09, 92 total profiles.
Scope: all 13 Cisco and all 19 HPE records inspected locally for CPU families, processor counts, DIMMs/channels/DPC, GPU options, cooling, lifecycle, dates, sources and coverage. Fresh official-document verification concentrated on AMD platforms, unusual memory topology, accelerator support and lifecycle. This is not a claim that every SKU in every QuickSpecs has been requalified. No app files changed.

P1 — Two Cisco MI210 paths are omitted from supported-product discovery.
Observed: ucs:c245 and ucs:x215 have gpuOptions=[] and amdGpuStatus=not-established. Catalog lines 6295/6328 and 7329/7363. Finder hides not-established relationships by default for a selected accelerator, so MI210 searches miss both.
Official evidence:
1. C245 M8 current spec sheet Rev A.41, 7 September 2026, Table 14, printed page 34: UCSC-GPU-MI210, 300 W / 64 GB, up to three GPUs, slots 2/5/7. Associated text requires GPU low-profile heatsinks, air blocker, air duct, and UCS-P100CBL-240-D power cable. This is the available-option table, not just spare parts.
https://www.cisco.com/c/dam/en/us/products/collateral/servers-unified-computing/ucs-c-series-rack-servers/ucs-c245-m8-sff-rack-server.pdf
2. X440p spec sheet, Table 4 printed page 9: UCSX-GPU-MI210 on UCSX-440P-D with M8, risers 1A/2A, maximum two; footnote excludes X210c. Requires appropriate X9416 X-Fabric modules and mezzanine adapter.
https://www.cisco.com/c/dam/en/us/products/collateral/servers-unified-computing/ucs-x-series-modular-system/x440p-specsheet.pdf
3. UCS Manager 4.3 release notes explicitly associate UCSX-GPU-MI210 with X215c M8 and UCSC-GPU-MI210 with C245 M8; X215c min 4.3(6a), C245 addition under 4.3(5c).
https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/release/notes/b_release-notes-ucsm-4_3.html
4. Intersight 5.3(0.250001) release notes also explicitly support MI210 with X215c.
https://www.cisco.com/c/en/us/td/docs/unified_computing/Intersight/Server-Firmware/4_3/b_intersight_server_fw_rn_4_3.html
Recommendation: model both qualified hardware routes, preserve firmware/PID/riser/CPU pairing scope and independently unverified availability. Do not generalize X440p support to the X580p. Existing caution about X580p is useful but does not justify omitting X440p.

P1/P2 — HPE cooling filters still produce false negatives.
Observed: DL325 Gen12 and DL345 Gen12 are Air-only, with no supportedCooling alternatives. Catalog lines 8465 and 8832; source work/fae-hpe.json lines198/308. Finder coolingOptions (work/finder.js37) therefore excludes both for Liquid.
Official DL325 QuickSpecs lists Direct Liquid Cooling Cold Plate Module P80827-B21, plus required whole-rack infrastructure; DL345 lists P81123-B21. Both explicitly advertise DLC as an option. DL325 also has a closed-loop internal liquid module, which is different from facility DLC and should not be flattened into an ambiguous liquid label.
https://www.hpe.com/us/en/collaterals/collateral.a50009232enw.html (Power and Cooling; web lines1589–1607)
https://www.hpe.com/us/en/collaterals/collateral.a50009233enw.html (Power and Cooling; web lines1603–1607)
Also DL525 Gen13 is Configuration-dependent with no supportedCooling, even though HPE's product page expressly says Air and DLC. Thus it disappears under either filter despite the announced relationship.
https://www.hpe.com/be/en/products/compute/proliant/dl525-gen13.html
Recommendation: audit structured cooling across remaining HPE models, add recorded air/DLC alternatives and exact conditions, preserve announced lifecycle for Gen13. Clearly distinguish facility DLC vs closed-loop liquid cooled with room air.

Assessment: substantially better learning and shortlisting experience, with unusually good memory topology and scoped lifecycle treatment. However, the two Cisco MI210 omissions are directly contrary to the core 'which platforms support AMD products' use case; combined with cooling false negatives and missing HPE installed-base profiles, these prevent treating the current catalog as an exhaustive AMD support index. Improve documented coverage/data completeness before more visual work.
